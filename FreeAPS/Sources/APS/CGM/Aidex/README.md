Портирование протокола из [Juggluco](https://github.com/j-kaltes/Juggluco)
(GPL-3.0, автор Jaap Korthals Altes) на Swift для iAPS 8.x.

## Протокол

### Серийный номер
**10 символов** с коробки (например `222225C99G`).
Он же — суффикс BLE-имени: `AiDEX X-222225C99G`.

### Вывод ключей — `mkiv.cpp`

```
snToBytes(c):  '0'-'9' → c-0x30
               'A'-'Z' → c-0x37
               'a'-'z' → c-0x57

IV      = MD5( snToBytes(SN)[i] * 17 + 0x13 )   // постоянен, для всех операций
askKey  = MD5( snToBytes(SN)[i] * 13 + 61   )
```

Ключ **не секретный** — выводится из номера на упаковке.

### Обмен ключами

1. `askKey` (16 байт) → **F001** (write with response)
2. Нотификация **F001** → 16 байт **мастер-ключ** (`keys[0]`, `aidexXSaveKey`)
3. Чтение **F002** → 17 байт
4. AES-128-CFB, ключ **мастер-ключ** (НЕ askKey), постоянный `IV`
5. Байты 0–15 = сессионный ключ (`keys[1]`), байт 16 = CRC8 Maxim
6. Дальше всё шифруется **сессионным** ключом

Сохраняется **мастер-ключ** (`keys[0]`). Сессионный ключ НЕ сохраняется:
при каждом подключении сенсор выдаёт новый, зашифрованный мастер-ключом,
мы читаем его из F002 (`aidexXstartCommand`). Аналог `keywhenconnecting`
в Android-версии — это «мастер-ключ уже есть», а не «сессионный ключ
переиспользуется».

### Команды F002 (с CRC16 в хвосте)

| Байты | Назначение |
|---|---|
| `10 C1 F3` | старт |
| `35 01 4E F7` | старт, если время известно |
| `21 B3 D5` | запрос времени старта |
| `22 D0 E5` | запрос последнего доступного ID |
| `23 <id16> <crc16>` | запрос истории с ID |
| `20 <время 9 байт> <crc16>` | запись времени в сенсор |
| `31 01 8A 3B` | запросить запись времени |
| `11 E0 E3` / `34 01 7F C4` | ответы на `0x134` / `0x135` |
| `F2 AD 2E` | отвязать |
| `F3 8C 3E` | сбросить привязку |

### Коды ответов

| Код | Обработка |
|---|---|
| `0x0110` | deviceInfo — прошивка, срок жизни, модель |
| `0x0111` | onceOld — одиночная запись `LastPast` |
| `0x0020`/`0x0120` | нужно время → `21 B3 D5` |
| `0x0121` | localStartTime → сохраняем старт сенсора |
| `0x0122` | lastValue → последний ID на сенсоре |
| `0x0123` | pastValues → пачка истории |
| `0x0124` | rawPastValues → игнорируется (как в оригинале) |
| `0x0131` | сенсор просит записать время |
| `0x0134`/`0x0135` | → `11 E0 E3` / `34 01 7F C4` |
| `0x01F2`/`0x00F2` | отвязка удалась / не удалась |
| `0x01F3`/`0x00F3` | сброс удался / не удался |

### Данные

**Текущая глюкоза** (F003, 15 байт):
```
байт 0     тип (3 = сенсор завершён)
байт 3     тренд (int8)
байты 4-5  минут от старта (uint16 LE)
байты 6-7  glucose:10 | warmup:1 | unknown:4 | valid:1
```

**История** (`0x0123`): `[код 2][startID 2][HistoryGlucose × N]`,
каждая запись **2 байта**: `glucose:10 | warmup:1 | unknown:4 | valid:1`.
ID инкрементируется на 1 — записи идут **поминутно**.

**Время записи**: `baseStart + secondsRemainder + id * 60` (`java.cpp: id2time`),
где `id` — сквозной (абсолютный) индекс, см. ниже.

**Глюкоза в мг/дл**, валидный диапазон **18–800**.

**Тренд**: поле `int8`, скорость в десятых мг/дл/мин.
`rate = trend * 0.1` (`java.cpp: AidexTrend2RateOfChange`).
Шкала (`rate2changeindex`): ≤−2 быстро вниз, ≤−1 вниз,
≤1 ровно, ≤2 вверх, иначе быстро вверх.

### Рекламные пакеты

Второй, пассивный канал: глюкоза в BLE-рекламе без шифрования,
с CRC32 (нестандартный seed из суммы четырёх uint32 по модулю
`0x7FA777`). Разбирается при сканировании — даёт последнее
значение и два предыдущих.

### Индексы и перезапуск сенсора

Сенсор нумерует записи от **своего** старта. Если сенсор перезапустили,
его нумерация обнуляется, а сквозная — нет. `java.cpp` держит три величины:

| Поле в `java.cpp` | Здесь | Смысл |
|---|---|---|
| `getinfo()->starttime` | `baseStart` | базовое время, ставится **один раз** |
| `getinfo()->patchState` | `secondsRemainder` | остаток в секундах |
| `getinfo()->starthistory` | `indexShift` | сдвиг индексов в минутах |

```
getRestartTime() = baseStart + secondsRemainder + indexShift*60
id2time(id)      = baseStart + secondsRemainder + id*60
siAddedIndex(i)  = i + indexShift          // сенсорный ID → сквозной
askHistory:  relID = абсолютныйID - indexShift   // обратно в сенсорный
```

При обнаружении нового времени старта (`0x0121`):

```
если базы нет или истории нет  → baseStart = новое, сдвиг 0
иначе если новое > текущего    → diff = новое - baseStart
                                 indexShift = diff/60
                                 secondsRemainder = diff%60
иначе (новое < текущего)       → ошибка, игнорируем
```

`indexShift` применяется **ко всем** входящим ID: `onceOld`, `lastValue`,
`pastValues`, текущая глюкоза с F003 и рекламные пакеты
(`java.cpp` строки 198, 386, 446, 596, 835).

## Что реализовано

- Обмен ключами + переиспользование сохранённого мастер-ключа
- Текущая глюкоза по F003 с проверкой CRC16
- **История**: `lastValue` → `askHistory` → `pastValues` → цикл до конца
- **Время сенсора**: чтение `localStartTime`, запись `writeTime`
- **deviceInfo**: прошивка, срок жизни сенсора
- **Рекламный канал** как пассивный источник
- **Сдвиг индексов при перезапуске сенсора** (`siAddedIndex`)
- Отвязка и полный сброс привязки
- Срок жизни сенсора в UI (`cgmLifecycleProgress`)
- Сохранение состояния между запусками (`rawState`)
- **Режим ежеминутных показаний** — опрос истории раз в минуту
  (по умолчанию сенсор шлёт текущее значение каждые 5 минут)

## Что осталось за рамками

1. **`0x0124` rawPastValues** — в оригинале тоже ничего не делает
   (`return sizeZero`), так что это не пробел, а поведение как в Juggluco.

2. **Не компилировалось и не тестировалось на железе.** Это главное.

### Закрытые вопросы

Ранее я записал в пробелы два пункта, которые при разборе исходника
оказались одним механизмом и теперь реализованы:

- «пересчёт ID при перезапуске» и «`historyBase` всегда 0» — это
  одно и то же поле `getinfo()->starthistory`. Оно инициализируется
  нулём (`SensorGlucoseData.hpp`, все конструкторы `Info`) и
  становится ненулевым только после перезапуска сенсора.
